# Tasks: Core Loop — Reconciliation Engine

**Input**: Design documents from `/specs/001-core-loop/`

**Prerequisites**: `plan.md`, `spec.md`, `research.md`, `data-model.md`, `contracts/{rest-api.md,toml-grammar.md}`, `quickstart.md`

**Tests**: Required for this feature. Three layers per `research.md` R-010:
- **Unit** (default tag): table-driven against mocks, covers diff/parser/security/labels/auth/store wiring
- **Docker integration** (`//go:build dockerd`): real `dockerd` socket; runs locally with `make test-integration`; CI optional
- **End-to-end** (Phase 8): `quickstart.md` walked end-to-end against the compiled binary

**Organization**: Five user stories from spec.md (SC-001-1 deploy through SC-001-5 list). Phase 1 (Setup) and Phase 2 (Foundational) hold the heavy lift — most of this feature is shared infrastructure that every user story leans on. Phases 3–7 are thin: a CLI command + integration test per story. Phase 8 (Polish) closes spec success criteria SC-006/SC-007 and runs the quickstart validation.

## Constraint reminders

- `CGO_ENABLED=0` for production binaries (overridden only at the test step).
- Every state-store/runtime call carries `project string` (constitution §III).
- Every container creation runs `security.Apply()` before submitting to Docker (constitution §II — enforced inside `runtime/docker`, not in callers).
- Every interface method that does I/O takes `context.Context` first (constitution §IV).
- Errors wrap with `fmt.Errorf("pkg/<impl>: %w", err)`.
- Logging via `slog` JSON to stderr.
- API has no anonymous endpoints (constitution §II).

## Notes

- The reconciler is concrete code by design (Complexity Tracking deviation #1). When v1.0 multi-node arrives and we need a cluster-wide reconciler, the diff function (`Compute`) is already pure — the only thing that needs swapping is who-sees-which-services and who-runs-actions, which becomes a coordinator wrapping the same `Compute`.
- The `proxa server` daemon (Complexity Tracking deviation #3) is the spec's missing FR. Tasks T049 and the quickstart make it explicit.
- The "naive remove-then-create" replace strategy (Complexity Tracking deviation #2) is encoded in T037 (`action.go`). Feature 002 will introduce a `Strategy` type that selects between start-first / stop-first, gated on Health checks landing.
- The `dockerd`-tagged integration tests (T032, T053–T063) are skipped in default CI. A separate workflow (T064) gates them behind a PR label so high-confidence work can opt in.
- The two test layers above the unit layer (`dockerd` and `e2e`) require a real Docker daemon. Document in CLAUDE.md (already covered by `docs(repo)` task in Polish if needed).
- After this feature lands, the foundation interface stubs (`noop*` types in `internal/runtime`, `internal/store`, etc.) are still useful for future tests in unrelated packages. They stay.
